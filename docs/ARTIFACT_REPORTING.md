# 最終Boxアセットの報告形式

## 3Dプレビューを先に示す

最終成果物を報告するときは、チャット内にThree.jsの操作可能なBox Impostorプレビューを置く。ブラウザがWebGL2に対応していない場合は静止画像に切り替え、ダウンロード用ZIPのリンクを併記する。3Dが表示できたかどうかは、確認した実行環境ごとに区別する。

プレビューの実装は `web/chat_viewer.html` と `web/chat_loader.mjs`。公開済みの `.box.zip` を取得して展開し、既存の `web/viewer.mjs` と `worker/runtime.mjs`、`three-impostor` で復元する。アトラスの6枚を単純に立方体へ貼るものではない。ブラウザへモデルの重みを送信する必要はない。

新しい成果物では `chat_viewer.html?zip=公開ZIPのURL` を利用する。ZIPはHTTPSで公開し、URLを固定する。バージョンのある成果物を使用する場合はコミットSHAのURLを選ぶ。外部サービス側の応答やチャットのブラウザ制限によって、読み込みが失敗する場合はある。

## 成果物と証拠

- 完成した `.box.zip` へのリンク。SHA-256、ファイル容量、アセットIDを添える。
- 6方向の採用数とフォールバック数。輪郭IoUの範囲を示し、採用と視点の正確さを同一視しない。
- 幾何・PBRマップの保存前後ハッシュ。色だけを変更したのか、形状も再ベイクしたのかを区別する。
- 保存済みZIPを別ディレクトリへ展開し、18視点の再読込比較を実施。色・深度の差と判定結果を記録する。
- 面間の色差の計測値。とくに最悪の面対と、サンプル数・検査条件を明記する。
- モデル・LoRAの版、入力画像と権利、実測したハードウェア環境を記載する。

推論の成功、輪郭による採用、面間の見た目、保存ファイルの忠実な復元は、それぞれ別の判定として示す。保存・再読込の誤差が0でも、各方向の色が一致したとは限らない。

## 実機で再検査する方法

Windows版EdgeのSwiftShaderを使う環境では、GPU推論を実行せずにチャット向けビューアと保存済みBoxを確認できる。

```sh
BI_SOFTWARE_GPU=1 BI_CHROMIUM='C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe' \
  scripts/wsl-windows-node.sh tests/chat_viewer_smoke.mjs .test-output/chat-preview.png
```

テストは公開ZIPの取得から復元までを行い、元GLBとの比較、視点切替、透視・正投影を確認する。同じコマンドの末尾に `--opaque` を追加すると、URLを持たない埋め込み画面を模した `about:blank` で復元とSHA-256検証を試せる。単体テストや従来のComfyUI統合テストを置き換えるものではない。
